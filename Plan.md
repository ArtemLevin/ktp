# KTP 3.0 — детализированный план дальнейшей работы

Актуально на **09.09.2026**. Последний содержательный baseline `main` — merge **«Complete grade 6 Vilenkin course (#60)»**, commit `84a7781c285a694a7ffffe80d892dfa64ef6ad88`.

## 1. Цель следующего этапа

KTP 3.0 уже имеет непрерывную базовую вертикаль математики 5–6 классов и алгебры 7–11 классов. Следующий крупный этап — построить непрерывную геометрическую вертикаль 7–11 классов, затем закрыть пять альтернативных линий «Конструктор», сохраняя единые требования к методике, архитектуре, QA и UX.

Целевое состояние проекта:

- все 17 учебных линий из `js/data.js` имеют полноценные тематические web-модули;
- для каждой основной учебной линии существует поурочная декомпозиция в пределах утверждённой программы;
- каждый урок содержит теорию, разобранные примеры, тренировку, домашнюю работу, самостоятельную работу в 6 вариантах и поурочный контроль в 6 вариантах;
- тематические самостоятельные и контрольные работы вынесены в `assessments/`;
- цифровые лаборатории создаются только там, где интерактивность усиливает понимание;
- документация и QA отражают фактическое состояние `main` без дрейфа.

# Этап 3. Непрерывная вертикаль геометрии 7–11 классов

**Приоритет: P1. Следующая основная работа.**

Геометрию реализовывать последовательно по классам. Для неё требуется повышенный стандарт визуального QA: чертёж является частью математического утверждения и должен соответствовать условию, обозначениям и взаимному расположению объектов.

## 3.1. Общий геометрический фундамент

До массового наполнения:

- определить общий формат данных для геометрических объектов;
- определить единый способ подключения SVG/Canvas моделей;
- создать reusable-компоненты для точек, прямых, отрезков, углов, окружностей и многоугольников;
- разделить статический учебный чертёж и исследовательскую лабораторию;
- ввести QA-критерии соответствия чертежа условию;
- обеспечить корректное масштабирование на мобильных устройствах и при печати;
- определить API для подписей, вспомогательных линий, равенств, параллельности и перпендикулярности;
- подготовить базовые accessibility-требования для интерактивных геометрических сцен.

Результат подпункта — reusable geometry layer, который используется всеми пятью линиями Атанасяна.

# Этап 5. Единый слой тематических assessments

**Приоритет: постоянный для каждой новой линии.**

Тематические работы создаются одновременно с завершением каждой тематической серии.

Стандарт одной тематической ячейки:

- самостоятельная работа — 6 вариантов;
- контрольная работа — 6 вариантов;
- единая шкала баллов внутри комплекта;
- ответы;
- критерии;
- печать одной версии или полного комплекта;
- режим учителя;
- отсутствие дословного копирования заданий учебника.

Автоматический QA должен проверять:

- одинаковое число задач между вариантами;
- одинаковую максимальную сумму баллов;
- эквивалентную структуру навыков;
- отсутствие фактически одинаковых вариантов;
- численные ответы программно там, где это возможно.

# Этап 6. Масштабирование цифровых лабораторий

**Приоритет: P2, с опережающей разработкой geometry primitives на этапе 3.**

## 6.1. Правило создания

Лаборатория создаётся, если ученик может исследовать зависимость, увидеть причинно-следственную связь или проверить гипотезу. Декоративная анимация сама по себе основанием для отдельной лаборатории не является.

## 6.2. Reusable-блоки

Развивать общие компоненты:

- координатная система;
- параметрический график;
- числовая прямая;
- геометрический SVG scene;
- 3D scene;
- таблица значений;
- slider/input controls;
- карточка «что наблюдать»;
- серия исследовательских экспериментов;
- self-check;
- сохранение/сброс параметров.

## 6.3. Accessibility

Каждая лаборатория должна иметь:

- текстовую альтернативу ключевого вывода;
- управление с клавиатуры;
- понятные `label`/ARIA;
- достаточные размеры controls;
- корректный mobile layout;
- отсутствие зависимости понимания только от цвета.

# Этап 7. Автоматизация QA и CI

**Приоритет: P1/P2.**

Текущая база уже включает профильные gate 5 и 6 классов и единый regression gate пяти основных алгебраических линий. По мере добавления геометрии требуется перейти к системному validator layer.

## 7.1. Course validator

Создать общий скрипт, который проходит по `js/data.js` и проверяет:

- наличие content для заявленной готовой линии;
- соответствие числа content-файлов тематическим ячейкам;
- наличие topic HTML;
- наличие series/index/lesson страниц;
- суммарное число уроков;
- глобальную последовательность номеров;
- отсутствие пропусков и дубликатов;
- валидность ссылок.

## 7.2. Content schema validator

Проверять обязательные поля тематических модулей и уроков:

- objectives / expectedResults / prerequisites;
- theory / examples / mistakes;
- practice / diagnostic / homework / summary;
- source;
- локальный и глобальный номер урока;
- самостоятельную и контроль в 6 вариантах;
- максимальные баллы и ответы.

## 7.3. Math-specific validation

Автоматизировать, где возможно:

- подстановку корней уравнений;
- дискриминанты и корни квадратных уравнений;
- линейные системы;
- координатные вычисления;
- значения функций;
- простые вероятности;
- диапазоны параметров лабораторий.

Для геометрии дополнительно ввести проверки согласованности данных чертежа с условием и ручной визуальный review gate.

# 13. Архитектурное правило на весь дальнейший цикл

При расширении до 17 линий масштабирование копированием UI/JS в каждую тему не допускается.

Переиспользовать и развивать общие слои:

- `content/registry.js`;
- `topics/topic-page.js`;
- `lessons/lesson-page.js`;
- `lessons/lesson-index.js`;
- `lessons/series-adapter.js`;
- `lessons/compressed-loader.js`;
- `assessments/assessment-page.js`;
- `assessments/compressed-loader.js`;
- общие компоненты лабораторий;
- будущий geometry/3D runtime.

Если один и тот же новый паттерн появляется минимум в двух-трёх линиях, он рассматривается как кандидат на общий компонент.

Главный критерий следующих релизов: ученик должен иметь возможность открыть любую готовую страницу без учителя, понять основную идею темы, увидеть корректный образец решения, выполнить тренировку, проверить себя и перейти к следующему шагу.
