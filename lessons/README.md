# Поурочные модули KTP 3.0

Каталог `lessons/` хранит поурочную декомпозицию тематических ячеек KTP. Один урок имеет собственный URL и использует общий renderer, поэтому учебный контент отделён от UI.

Актуальность статуса: **06.09.2026**.

## Адресная схема

```text
lessons/<учебная-линия>/<номер-темы>/
├── index.html          # каталог уроков темы
├── series.js           # метаданные серии
├── 01.html
├── 02.html
├── ...
└── data.js / data/ / packed-*.js
```

В зависимости от объёма серии данные могут храниться по одному уроку в файле, тематическими блоками или в gzip/Base64-пакете. Сжатые серии загружаются общим `compressed-loader.js`.

## Общие runtime-компоненты

```text
lessons/
├── lesson-page.js       # renderer одного урока
├── lesson-index.js      # renderer каталога
├── lesson-page.css      # общий адаптивный стиль
├── series-adapter.js    # адаптация данных серии и подключение лабораторий
├── global-numbering.js  # глобальная нумерация курса
├── compressed-loader.js # загрузка gzip/Base64 runtime
└── topic-links.js       # ссылки только на реально опубликованные серии
```

## Требования к одному уроку

Полноценный объект урока содержит:

- локальный и глобальный номер;
- название, учебную неделю и источник;
- цели и prerequisites;
- теоретические блоки;
- минимум два полноценных разобранных примера;
- типичные ошибки;
- тренировку от базового уровня к переносу;
- обязательную и дополнительную домашнюю работу;
- самостоятельную работу в 6 вариантах;
- поурочный контроль в 6 вариантах;
- итоговые тезисы;
- ссылку на отдельную цифровую лабораторию, когда она методически оправдана.

Для серий с генераторами проверочных вариантов допускаются общий assessment-factory и локальные генераторы, если итоговые варианты проходят математическую и структурную проверку.

## Навигация

```text
тема KTP → каталог серии → урок → соседний урок / тема / лаборатория
```

`series.js` создаёт `window.KTP_LESSON_SERIES`, файлы данных добавляют уроки в `lessons`, а общий renderer формирует интерфейс. Для крупных серий `compressed-loader.js` предварительно восстанавливает тот же runtime-объект из сжатого payload.

## QA перед merge

Для каждой новой или изменённой серии проверяются:

1. число уроков и уникальность `id`;
2. соответствие глобальной нумерации календарной последовательности;
3. наличие обязательных структурных блоков;
4. суммы баллов во всех вариантах;
5. ответы, проверки разобранных примеров и условия задач;
6. отсутствие `NaN`, `Infinity`, `undefined` и пустых ответов;
7. синтаксис JS и успешная загрузка runtime;
8. при сжатии — корректная распаковка payload;
9. переходы каталог → урок → соседний урок → тема KTP;
10. ссылки на assessments и отдельные цифровые лаборатории;
11. мобильная компоновка и печать;
12. отсутствие временных QA-файлов;
13. синхронизация документации при изменении статуса линии.

Для первых пяти серий 5 класса действуют `scripts/qa-grade5-vilenkin-topic01.mjs` … `scripts/qa-grade5-vilenkin-topic05.mjs`; план всей линии отдельно защищён `scripts/qa-grade5-vilenkin-plan.mjs`.

## Правило против документального дрейфа

Статус линии нельзя выводить из наличия директорий или HTML-каркаса. Серия считается готовой только при одновременном выполнении условий: данные уроков загружаются в заявленном количестве, `lessons/topic-links.js` содержит опубликованную ссылку, проверки 6+6 валидны и профильный QA проходит успешно.
