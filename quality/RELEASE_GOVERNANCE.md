# KTP 3.0 · Протокол безопасного релиза

Дата базовой проверки: 30.10.2026. Базовый commit: a3c6d1e6a25bd3e02792f9b9a9f7d5e9fb89c270.

## Установленные факты

- В календарной модели 17 линий и 121 адресная страница темы.
- 12 учебниковых линий содержат 87 content-модулей, 1190 поурочных страниц и 87 тематических assessment-комплектов.
- Пять линий «Конструктор» содержат 34 тематические страницы без content-модулей.
- Перед аудитом ветка main имела protected=false, а список rulesets был пуст.
- GitHub Actions включал множество специализированных предметных проверок, привязанных к путям. Поэтому «все показанные запуски зелёные» не равнозначно обязательному запуску всех предметных проверок перед любым merge.
- Исходные банки ответов преподавателя находятся в публичном репозитории. Ученические страницы геометрии 11 класса используют student-data.js без полей ответа и решений, однако доступ к публичным источникам сохраняется.

## Введённый сквозной gate

.github/workflows/release-integrity.yml, job: integrity.

Проверяется:
1. Целостность календарных идентификаторов и границ 34-недельного плана.
2. Наличие адресных тематических страниц для всех 17 линий.
3. Соответствие content-файлов учебным страницам для наполненных линий.
4. Наличие годовой поурочной декомпозиции и последовательной нумерации уроков.
5. Наличие двух тематических работ для каждого наполненного модуля.
6. Наличие локальных CSS/JS-файлов, явно подключённых HTML.
7. Отсутствие прямого подключения преподавательских файлов в ученических assessment-entrypoint.

Эта проверка структурная: она не доказывает правильность математики, работоспособность динамически собираемых URL, безопасность всех публичных данных или качество учебной методики. Профильные математические и браузерные QA сохраняются.

## Требуемая настройка GitHub, которую нельзя выполнить текущим подключением

В репозитории открыть Settings → Rules → Rulesets → New branch ruleset (либо Settings → Branches → Add branch protection rule, если используется классическая защита).

Для main:
- Require a pull request before merging;
- Require status checks to pass before merging: точное имя check **integrity**, опубликованного workflow **Release Integrity**;
- Block force pushes и branch deletion;
- Do not allow bypasses, если это соответствует принятой роли владельца;
- До настройки стабильной review-практики у единственного разработчика не делать обязательным чужой approval, который невозможно получить.

После включения создать тестовый PR с намеренной ошибкой в копии одной статической ссылки и убедиться, что gate блокирует merge. Исправить ошибку и подтвердить разблокировку. Не выполнять этот негативный тест на main.

## Контроль доступа к ответам

Разделение student-data.js и data.js — мера изоляции интерфейса, не механизм конфиденциальности. Нельзя считать ответы защищёнными, пока полный исходный банк находится в публичном Git.

Для конфиденциальных контрольных:
1. Держать ключи/решения в приватном хранилище, вне публичной истории и GitHub Pages artifact.
2. Публиковать самостоятельные ученические задания без ответа, критерия преподавателя и скрытых payload.
3. Выдавать преподавательский ключ через авторизованный канал.
4. Не копировать приватные исходники в build или публичную папку сайта.
5. Для уже опубликованных вариантов считать ключи раскрытыми и обновлять банк после миграции. Удаление файла из новой версии Git не устраняет прошлую публичную историю.

До такой миграции использовать существующие открытые банки как тренировочные/демонстрационные и не применять их в качестве конфиденциальных экзаменационных вариантов.

## Резервирование данных KTP

Текущее приложение хранит план/факт, заметки и историю в localStorage (ключ ktp-2026-27-v3). Серверной синхронизации нет.

Промежуточный регламент: после существенного изменения расписания экспортировать JSON, хранить копию отдельно от браузера, периодически проверять восстановление на тестовом профиле. Импорт следует проводить только из доверенного источника; техническое изменение резервирования и восстановления выделяется в самостоятельный PR с тестами миграции и обратной совместимости.
